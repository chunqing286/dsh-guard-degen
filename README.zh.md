# dsh-guard-degen

[![CI](https://github.com/chunqing286/dsh-guard-degen/actions/workflows/ci.yml/badge.svg)](https://github.com/chunqing286/dsh-guard-degen/actions/workflows/ci.yml)
[![npm](https://img.shields.io/npm/v/dsh-guard-degen.svg)](https://www.npmjs.com/package/dsh-guard-degen)

退化守卫：给 DeepSeek Harness 装一道「模型符号流退化」的护栏，并附赠工件/会话的清理工具。

## 为什么需要它

某些模型（实测集中在 MiniMax 系列）在思考阶段会退化成单字符长跑，例如：

```
⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ ⇒ …
```

退化**不一定**是同一个符号的重复，也可能是**多字符单元整段整段地重复**：

```
⇒⇒§ ⇒⇒§ §

⇒⇒§ ⇒⇒§ §

…（整段整段地重复下去）
```

这种输出会一路写进会话文件、思考内容，甚至被模型自己写进仓库里的文档和源码。
一旦会话被污染，「继续」只会得到更多同样的符号流——会话本身已经不可用，
但**文件里的污染会留给下一个会话**，形成越积越多的脏工件。

本插件做四件事：

1. **流式拦截**——在模型输出到达界面前检测符号游程，按策略截断/消毒，避免污染进入会话与磁盘。
2. **写后校验**——写文件类工具执行后回读文件，发现退化内容就阻断并把反馈回灌给模型。
3. **重试与换模**——退化导致请求失败时自动重试（同模型 N 次），必要时切换到指定模型。
4. **工件与会话清理**——扫描仓库与历史会话，产出报告，由你选择哪些要修（默认只预览，不写盘）。

工件治理覆盖**两种退化形态**：单个符号的游程，以及**多字符单元整段重复**
（例如 `⇒⇒§ ⇒⇒§ §` 反复出现）。勾选条目后点「预览修复」，界面直接给出
**红/绿对照**（红＝修复前的原文，绿＝修复后的样子），确认无误再落盘。

「多字符单元整段重复」这一形态在**四个地方**都受治理，各有各的开关与份数阈值：

| 位置 | 开关 | 份数阈值 | 默认 |
| --- | --- | --- | --- |
| 工件修复 | `artifacts.unitRun` | `artifacts.unitRepeats` | 开 / 4 |
| 流式守卫 | `stream.unitRun` | `stream.unitRepeats` | 开 / 4 |
| 工具守卫 | `toolGuard.unitRun` | `toolGuard.unitRepeats` | 开 / 4 |
| 会话遮蔽 | `sessions.unitRun` | `sessions.unitRepeats` | 开 / 4 |

关掉某个开关，只是那一个地方退回「只管单符号游程」；其它地方照旧，
四道守卫互不牵连。份数阈值同理——四处各调各的，调大更宽松，调小更敏感。

## 安装

**一条命令**（包已发布到 npm）：

```sh
dsh plugin --profile <你的 profile> add dsh-guard-degen
```

`<你的 profile>` 换成宿主实际使用的 profile 名（`dsh web` 通常是 `web`，
桌面端应用用的是它自己的 profile，名字未必相同）。

也可以直接从仓库装：

```sh
dsh plugin --profile <你的 profile> add github:chunqing286/dsh-guard-degen
```

也可以在 DSH 界面里点一下：**插件 → 发现**，添加索引源
`https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json`，
搜「退化守卫 / guard degen」，点**安装**。

装好之后，插件自带的 `cordis.patch.yml` 会作为 bundle 层被应用，宿主半边与浏览器半边一起装上，
运行时会话和设置页里立刻能看见「退化守卫」分区。

### 手动安装

不想用包管理器的话，在
`$DSH_HOME/profiles/<你的 profile>/cordis.patch.yml` 里追加一条 insert：

```yaml
- insert:
    - id: guard-degen
      name: <指向插件目录的相对路径或包名>
```

`name` 里的相对路径**以该 patch 文件所在目录为锚点**（这是宿主 `dsh-app-boot` 的既定语义），
所以指向任何本地目录都可以；改成包名则需要该包能被解析（profile 的 `node_modules` 或安装自带包）。

走相对路径安装时，插件目录要能解析到自己的运行时依赖
（`@deepseek-ai/dsh-typert-protocol`、`@deepseek-ai/schemastery`，以及它们依赖的
`@deepseek-ai/cordis`、`@deepseek-ai/cosmokit`）；走 npm 安装则由 npm 自动装齐。

也可以走 profile 的 bundle 机制：在 profile 的 `package.json` 里写
`"dsh": { "profile": { "bundles": ["dsh-guard-degen"] } }` 并把包列进 `dependencies`，
插件自带的 `cordis.patch.yml` 会作为 bundle 层被应用。

宿主侧插件的 `Config` 是原生 Schemastery schema，因此设置页会自动渲染出配置表单；
插件自己在 **设置** 里注册了一个独立分区 **退化守卫**（与「插件」并列），
分区下面有三个页签，**每个页签各占一页**（互斥显示，不会叠在一起）：

- **配置**：全部配置的图形入口。
- **日志**：判定流水——每一次退化判定都记着命中了哪条规则、发生在哪个会话、
  守卫做了什么处置。列表带**会话ID**与**会话名称**两列，可以按会话筛选
  （下拉选会话，或按会话 ID / 名称做文本筛选）；点一条记录能看**检出的退化特征**
  （哪个单元重复了几次），以及**红/绿对照**（红＝治理前的退化原文，
  绿＝治理后留下的东西：净化时是折叠标记，截断时是「后面没有了」的说明；
  没有自动治理时绿行写明「只记录判定，未改写」）。误报反馈入口也在这里。
- **工件**：工件扫描报告、被污染会话列表，逐项勾选后再修复。

会话列表同时给出**会话标题**和会话 id；选中会话点「预览遮蔽」后，
界面直接给出**红/绿对照**（红＝遮蔽前原文，绿＝遮蔽后的标记），
不用再去翻生成的磁盘文件。

会话遮蔽有**两种内容方式**，工件页与会话视图里都能切换：

- `折叠成标记`：把整段退化折叠成 `〔退化内容已遮蔽×N〕`（默认）。
- `整段删除`：整段删掉，不留痕迹——**磁盘上的内容里一个字标记都不写**，
  对照视图的绿行显示的就是删完剩下的文字（符号是真的没了，
  不是「被换成了某一句话」）。整条内容都被删光时，绿行会写明「整条内容被删空了」。

切换之后**预览会立刻按新方式重算**，所以不用先落盘再回头看文件。

遮蔽还分**两种落地方式**（工件页与会话视图里都能切换）：

- `另存为副本`：把遮蔽后的内容写成新文件，原档不动（工件页默认）。
- `直接改写会话存档`：**会话视图里默认就是这一种**——遮蔽的就是眼前这个会话本身，
  不用再去别处找一份副本。

### 会话视图里的「退化守卫」

会话页的视图行里除了「对话 / 轨迹 / 上下文 / 编队」，还有一个 **退化守卫** 视图
（与它们并列），针对的就是**当前会话**：

- **工作区工件**：扫描范围是**当前会话所在的工作目录**（由宿主从会话存档头里解析，
  浏览器只传会话 id，不能自选目录），修的也是这个目录里的工件。
- **当前会话**：直接遮蔽当前会话存档里的退化内容，方式与工件页一致。

「执行遮蔽」默认**就地改写当前会话**：会话存档被原子替换（先写临时文件再改名），
原文件备份到 `~/.dsh/guard-degen/backups/`，写完回读复核。

三件事要清楚：

- **界面上的历史消息不会当场变**——对话视图是宿主内存里的内容，
  重新打开会话才能看到改写后的文本。
- **进行中的会话会继续追加**：改写之后宿主新写入的消息仍接在改写后的内容后面。
- **落盘前会以最新内容重算**：预览之后若又写入了新消息，遮蔽按最新内容重算一遍，
  不会把新消息抹掉。

## 命令

| 命令 | 作用 |
| --- | --- |
| `/degen-status` | 看当前守卫状态、规则表、最近判定 |
| `/degen-scan [路径…]` | 只读扫描工件（默认扫当前工作区），产出报告 |
| `/degen-fix <文件路径…>` | 修复指定文件里的退化内容（先备份再改写） |
| `/degen-clean` | 遮蔽当前会话里的退化内容（默认另存新档，原档保留） |
| `/degen-ack` | 把最近一次判定登记为误报，并调高对应规则阈值一档 |

## 配置要点

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 总开关 |
| `modelIncludes` | `[]` | 只守卫这些模型（留空＝全部模型） |
| `stream.reasoning` | `truncate` | 思考流策略：`off`/`truncate`/`sanitize` |
| `stream.text` | `sanitize` | 正文流策略 |
| `stream.holdbackChars` | `256` | 保留窗口：判定前不立即放行的字符数 |
| `stream.maxInterventionsPerCall` | `1` | 单次调用最多干预次数（防止反复改写） |
| `stream.unitRun` | `true` | 流式守卫是否治理「多字符单元整段重复」 |
| `stream.unitRepeats` | `4` | 流式守卫里单元重复多少份才算退化 |
| `toolGuard.mode` | `warn` | 工具参数里的退化：`off`/`warn`/`refuse` |
| `toolGuard.scope` | `all` | `all`/`write-only`/`oversized-only` |
| `toolGuard.unitRun` | `true` | 工具守卫是否治理「多字符单元整段重复」 |
| `toolGuard.unitRepeats` | `4` | 工具守卫里单元重复多少份才算退化 |
| `postExecute.enabled` | `false` | 写后校验开关（回读文件，有 IO 成本） |
| `postExecute.roots` | `[]` | 限定校验范围；留空＝工作区内 |
| `retry.policy` | `same-model` | `same-model`/`steer`/`no-retry` |
| `retry.maxSameModelRetries` | `1` | 同模型重试次数 |
| `retry.switchModel.enabled` | `false` | 是否允许自动换模型（需显式给 provider+model） |
| `artifacts.mode` | `collapse` | 修复方式：`collapse`（折叠成标记）/`remove`（删除） |
| `artifacts.apply` | `false` | 默认只预览，不写盘 |
| `artifacts.unitRun` | `true` | 是否治理「多字符单元整段重复」这类退化 |
| `artifacts.unitRepeats` | `4` | 单元重复多少份才算退化 |
| `sessions.mode` | `copy` | 会话遮蔽方式：`copy`（另存新档）/`replace`（覆盖原档） |
| `sessions.maskMode` | `collapse` | 会话遮蔽内容方式：`collapse`（折叠成标记）/`remove`（整段删除） |
| `sessions.unitRun` | `true` | 会话遮蔽是否治理「多字符单元整段重复」 |
| `sessions.unitRepeats` | `4` | 单元重复多少份才算退化 |
| `logging.enabled` | `true` | 判定流水落盘 |

运行时改配置会写 `~/.dsh/guard-degen/config.json`（覆盖 profile 层的值）。

## 安全边界

- **默认只读**：工件修复与会话遮蔽的 `apply` 默认 `false`，预览阶段一个字节都不写。
- **先备份后改写**：真正落盘时先写 `<文件>.degen-backup`，备份失败就不动原文件。
- **回读复核**：改写后重新读文件数残留游程，残留不为 0 会报错，不会假装成功。
- **按游程判定，不按单符号**：`★` 这类合法标记在真实仓库里存在，只有成串的游程才算退化。
- **多字符单元重复才算数，且只在符号区里找**：像 `⇒⇒§ ⇒⇒§ §` 这样整段整段重复的内容
  会另算一类退化（标记成 `〔退化单元×N〕`）；判定要求单元里**至少含一个非 ASCII 字符**，
  所以代码、表格、正常中文散文都不会被误判；单个符号的长跑仍归游程那条规则管，
  两边不会重复上报。
- **清完长游程剩下的碎片也要判**：退化内容常是「长游程 + 碎片」交替的样子，
  长游程被摘掉后碎片会贴到一起，拼出一个**新的**单元重复。
  所以单元判定是在「摘掉游程之后的残渣」上做的，一遍治理就把两者一起清干净——
  否则回读复核会判「复核未通过」，用户等于什么都没拿到。
- **浏览器端放宽不了阈值**：游程长度、符号集、单元份数阈值一律取自配置，
  绝不取自浏览器请求；页面要求更松的阈值会被忽略。
- **工具调用参数默认不清理**：会话遮蔽保留 tool-call 块逐字一致（配对关系不能破），
  实测约 24% 的污染位于工具参数内，因此不会被清除——这是有意的取舍。
- **只改模型自己产出的内容**：会话遮蔽仅处理 `assistant/message`（含 compaction 摘要）
  里的文本与思考；用户提问、系统提示、工具结果一律原样保留。
- **不越界写**：工件扫描/修复受 `artifacts.roots` 约束（默认当前工作目录），
  显式传入的文件列表也不能绕过根目录；符号链接目标与非 UTF-8 文件一律跳过。
  `/degen-fix` 会把根目录绑到你点名文件的所在目录，所以工作区以外的文件照样能修，
  但那棵树里的其它文件一个都不碰。
- **浏览器端不能指定落盘位置**：远程方法只透传白名单参数，输出/备份/审计路径由插件决定；
  遮蔽副本、备份、审计分别写在 `~/.dsh/guard-degen/{masked,backups,audit}/`，不落在会话目录里；
  遮蔽只接受 `~/.dsh/sessions` 之内的目标。
- **没有退化就不落盘**：会话里一段退化都没有时，遮蔽不会改写存档，也不会产生备份。
- **游程跨两个块时切断整条流**：宿主按块推送 delta，已经放行的内容收不回来。
  所以游程头部已经放行时，守卫**切断整条流**而不是只折叠尾巴——
  半折叠的标记既会少算符号数，又会把原始符号留在正文里。
  代价是这一段回答被截断，这正是该有的失败姿态：这条会话本来就要重开。
- **标记计数与正文一致**：宿主 assembler 里 block-end 的文本才是权威值，
  所以 `〔退化符号流×N〕` 也会在权威文本里同步改写——存档里的计数等于真正清掉的符号数。
- **符号链接目标一律不遮蔽**：目标是符号链接的会话文件直接拒绝（即使它解析后仍在会话根目录内），
  根目录判定又按真实路径比较，根目录里的链接改不动根目录外的文件。
- **干预上限用尽就截断，不放行**：单次调用的改写次数用完后再遇到退化，流会被截断并以
  error 结束——原始符号不会有机会进入会话。
- **配置不会带坏自己**：`setConfig` 先校验合并后的整体，非法值不落盘。
- **跳过的文件会被说出来**：单文件超过 `artifacts.maxFileBytes`（默认 8MB）时不会检查，
  这些文件会列在扫描报告的 `skippedTooLarge` 里并在界面提示——「没扫到」不等于「没问题」。

## 开发

```bash
node --test test/*.test.mjs
```

测试不依赖宿主运行时（除少数需要真实 cordis 的集成检查外）。

独立校验脚本在 `verify/`（用同一个 node 跑）：

| 脚本 | 证明什么 |
| --- | --- |
| `check-patch-config.mjs` | 自带的 `cordis.patch.yml` 与 schema 默认值一致 |
| `check-host-load.mjs` | 宿主类在真实 cordis 里能实例化，13 个远程方法都在 |
| `check-host-entry.mjs` | 宿主半边能在真实 cordis 上装载并起监听 |
| `check-remote.mjs` | 远程方法标记能被真实协议包识别 |
| `check-package-files.mjs` | 包清单指向的文件都存在（`npm pack --dry-run` 的等价物） |
| `check-mutations.mjs` | 每处修复都被用例钉住：改回缺陷状态必有测试变红 |
| `check-remove-mode.mjs` | 「整段删除」模式下磁盘上不留任何痕迹 |
